# 开发与调试说明

## 处理链路

1. WPF 界面收集目录、统一字段、逐图纸字段及人员签字设置。
2. `CadProcessingCore` 调用 `scan_all_frames.ps1` 批量扫描 DWG。
3. `old_frame_scan.lsp` 在 AutoCAD Core Console 内提取模型/布局对象。
4. `analyze_inventory.ps1` 将原始对象清单转为图框和图签候选。
5. 人工核对后，`run_frame_replacement.ps1` 调度逐文件替换。
6. `replace_frames.lsp` 删除已确认的旧图框/图签内容并插入新块。
7. `verify_replacement.ps1` 比对计划、源对象、输出对象及必填字段，生成最终验收报告。

## 当前关键规则

- 支持 A0、A1、A2及加长图框，按实际宽高而不是仅按基础规格匹配。
- 模型空间和布局空间分别识别。
- 布局炸开图框只在证明存在完整 ISO 外边界后处理；保留 VIEWPORT、裁剪多段线和非图签块。
- XREF、天正代理对象和松散文字可能需要回退识别或人工核对。
- 无法确认图名、图号或删除目标时，应标记待核对/失败，不允许静默叠写。
- 单文件失败不得中止整个批次。

## 最低验证要求

修改识别或替换逻辑后，至少执行：

1. `build.ps1` 编译通过。
2. 使用脱敏 DWG 扫描，核对图纸数、图框数、布局数。
3. 实际替换后重新扫描输出 DWG。
4. 检查 `最终验收报告.csv` 中计划图框、源图框、源图签、新图框和新图签数量一致。
5. 打开 AutoCAD 抽查图名、图号、人员姓名、签字、比例、单位、布局视口及图框规格。

## Bug 资料

提交问题时应提供软件版本、AutoCAD/Core 版本、源文件名、模型或布局名称、预期结果、实际结果、问题清单、验收报告和截图。项目原图不得直接提交到仓库；请制作脱敏最小复现文件。
